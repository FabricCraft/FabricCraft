# Desktop and fabric-skin dependencies

The prototype creates a fabric surface from an ordered support boundary. It suggests points by projecting the reference in a selected axial direction and taking the convex hull using a monotone chain. At coincident projected coordinates it chooses the point farthest toward that side. The user can replace the suggestion with an ordered, concave boundary. The skin builder projects the boundary onto its dominant coordinate plane, checks for crossings with `robust`, triangulates the simple outline, and lifts those triangles back to the exact selected 3D points. It verifies that triangulation retains every directed boundary edge. The geometry represents an estimate with no material or contact model.

The `gui` lock includes platform packages beyond the Windows build. Its Windows GNU normal and build graph was inspected with `cargo tree --locked -p fabriccraft-cli --features gui --target x86_64-pc-windows-gnu -e normal,build --format "{p} | {l}"`. Besides MIT and Apache-2.0 and their alternatives, the selected dependencies carry Unicode-3.0, BSL-1.0, ISC or BSD terms and font-specific notices. The default egui fonts keep their applicable MIT, Ubuntu Font License and SIL OFL terms. Review the exact target graph and carry its notices when packaging a binary. [Bundled font terms](https://github.com/emilk/egui/tree/44cdd653e2317d300fb8a6c9c36b03f23991e803/crates/epaint_default_fonts/fonts)

The prototype uses an orthographic viewport and depth-based vertex and edge picking. Its layer ordering is intended for examining the proposed envelope. The source model remains read-only.

The Windows GNU release ran all workspace tests with the GUI enabled and opened a native window. The build used Rust 1.100.0 and its GNU import-library generator with a compatible assembler. Mixing an LLVM import-library generator with the bundled GNU linker produced a startup fault during this experiment.
